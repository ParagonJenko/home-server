Build the homelab in order, and prove each guardrail before the next one leans on it.

Kit: two Beelink NUCs, a Raspberry Pi, a 2×4TB DAS, and a 2TB USB HDD (PBS backup datastore, Stage E).

Work top to bottom. Every step is yours by hand, a script from configs/, or a check — don't retype script commands, run the file. Start at A0.

What each stage does
  • A — host base (NUC-1).
  • B — storage: build the media pool, break it on purpose.
  • C — container template.
  • D — internal DNS on the Pi (early — everything resolves through it).
  • E — media stack (NUC-1).
  • F — host base (NUC-2).
  • G — Frigate + PBS backups (NUC-2).
  • H — monitoring & alerting on the Pi (late — needs the containers).
  • I — remote access & final proof.
  • J — resilience & lifecycle.
  • K — local inference (future, optional).
How this page works
  • Fast path: on each box, run its bootstrap script — sudo ./bootstrap-nuc1.sh, then ./bootstrap-pi.sh, then ./bootstrap-nuc2.sh. Each prompts for what it needs (disks, the Pi's IP, secrets) and pauses at the manual bits. The stages below are the detail behind them.
  • Fill your values once in Your values — they appear in every command on the page.
  • Record every MAC and IP in the address register below as you go — it exports straight into network.md.
  • A script's real commands live in configs/; this page says which file and what it does.

A single workload filling up is normal, and must be handled gracefully.

The shared system filling up is catastrophic, and must be impossible. An alert saying “Frigate is pruning old video” is a success. A filesystem aborting at 100% is the only real failure, and it is designed out.

Power loss pauses the system; it never corrupts it.

A UPS and an ordered shutdown make a yanked mains cable a clean stop, not an aborted write — the fill rule's failure, designed out from the other direction. R22

The whole system rebuilds from off-box state alone — secrets included.

Docs, backups and every secret live somewhere no single dead box takes with it, so the stack comes back on hardware that has never seen it. R21 R17

Progress is stored in this browser only — it isn't shared with anyone else opening this page. Source of truth stays in the repo (github.com/ParagonJenko/home-server): rules.md owns the rule text, configs/ owns the runnable commands, network.md's address register owns every MAC and IP, storage.md's disk register owns which physical disk is which, and inventory.md / services.md / storage.md / network.md get updated in the same change as the thing they describe.

Your values

The only things this build can't know in advance. Type them once — every command on this page picks them up. Nothing leaves your browser.

Two values are missing on purpose

The Discord webhook URL and the Grafana admin password are credentials. They live only in files on the Pi — alertmanager/discord-webhook-url and .env, both gitignored, both chmod 600. Don't type them here: this is a published page, and a secret pasted into it is a secret you now have to rotate.
